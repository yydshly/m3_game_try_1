# UI_REDESIGN.md — Web UI 重构说明

> 本次重构将 Web UI 从"调试页面"升级为沉浸式 AI 推理游戏主界面原型。

---

## 1. 本轮 UI 重构目标

让用户打开页面后立刻理解：
- 我在哪里（当前地点）
- 当前时间和阶段
- 谁在场（在场 NPC 高亮）
- 我能做什么（动作按钮）
- 我拿到了什么证据（证据卡片）
- 最近发生了什么（事件日志）
- 下一步如何推进

---

## 2. 页面信息架构

```
┌─────────────────────────────────────────────────────┐

│ 场景舞台  │       剧情/对话区       │   右侧状态栏    │

│          │                        │              │

└─────────────────────────────────────────────────────┘
```

## 3. 主界面区域说明

### 3.1 顶部状态栏（Header）
- 标题、游戏时段、阶段徽章、当前位置、证据数量、已对话人数
- 连接状态指示灯

### 3.2 左侧场景舞台（Scene Stage）
- 地点名称 + 氛围描述卡片
- NPC 在场卡片列表：
  - **在场**：高亮边框 + "在场" 标签 + "盘问" 按钮
  - **不在场**：灰化 + 显示当前位置
  - **已对话**：额外 "已对话" 标签

### 3.3 中央剧情/对话区（Story Log）
区分消息类型，各自视觉不同：
- `entry-narrator`：斜体旁白，左侧蓝色竖线
- `entry-dialogue`：NPC 气泡 / 玩家气泡（右对齐）
- `entry-system`：紫色小字，左侧竖线
- `entry-investigate`：调查结果显示
- `entry-clock`：时钟分隔线
- `entry-gameover`：结局金色卡片

### 3.4 右侧状态栏（Right Sidebar）
- 当前状态（时段/阶段/位置）
- 持有证据（标签卡片）
- 公共事件记录

### 3.5 底部动作按钮区（Action Bar）
- 移动 / 调查 / 推进 / 指认分类显示
- enabled=false 的按钮禁用 + 显示 hint

### 3.6 对话输入弹层（Talk Modal）
- NPC 头像 + 名字 + 身份
- 预设问题快捷按钮
- 文本输入框
- 发送/取消按钮

---

## 4. 场景布局策略

每个地点用 CSS class 和文字描述区分氛围：
- 大厅、书房、厨房、走廊、餐厅等各有文字描述
- 当前地点名显示在场景舞台顶部
- 场景切换使用 `scene-flash` 覆盖层

---

## 5. 人物形象布局策略

- 每个 NPC 有稳定颜色 + 首字母头像
- 颜色与 NPC 角色对应（陈伯=金，林婉=红，苏苏=粉等）
- 头像在对话气泡和 NPC 卡片中统一使用
- 不使用真实图片，使用 CSS + 文字模拟

---

## 6. 与 `/api/action` 的关系

所有交互走 `/api/action`：
- 移动、调查、推进、指认：直接调用
- 盘问 NPC：点击"盘问"按钮 → 弹出输入层 → 输入后调用 `/api/action`，`type='talk'`

页面初始化：`POST /api/session`
状态刷新：每次 `/api/action` 响应中携带最新 `state`（含 `available_actions`）

---

## 7. 当前限制

- 无真实美术图，使用 CSS + 文字模拟
- 场景切换使用纯 CSS 动画，无图片过渡
- NPC 头像使用字母占位，无真实立绘
- 存档仍为单文件（`saves/save.json`）

---

## 8. 下一轮 UI 迭代建议

1. **场景区**：根据地点切换 CSS 背景色温（书房偏暖、保安室偏冷）
2. **证据板**：用卡片网格替代标签列表，显示证据来源
3. **人物关系**：增加 NPC 相互关系可视化（谁怀疑谁）
4. **时间轴**：在侧边显示时钟推进的时间线
5. **map.html**：评估是否能作为地图 UI 原型保留（当前 `map.html` 独立于本次重构）
