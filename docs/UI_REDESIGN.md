# UI_REDESIGN.md — Web UI 重构说明

> 本次重构将 Web UI 从"调试页面"升级为沉浸式 AI 推理游戏主界面原型。

---

## 1. 本轮 UI 重构目标

让用户打开页面后立刻理解：
- 我在哪里（当前地点）
- 当前时间和阶段
- 谁在场（在场 NPC 高亮）
- 我能做什么（动作按钮）
- 我拿到了什么证据（证据卡片）
- 最近发生了什么（事件日志）
- 下一步如何推进

---

## 3. 主界面区域说明

### 3.1 顶部状态栏（Header）
- 标题、游戏时段、阶段徽章、当前位置、证据数量、已对话人数
- 连接状态指示灯

### 3.2 左侧场景舞台（Scene Stage）
- 地点名称 + 氛围描述卡片
- NPC 在场卡片列表：
  - **在场**：高亮边框 + "在场" 标签 + "盘问" 按钮
  - **不在场**：灰化 + 显示当前位置
  - **已对话**：额外 "已对话" 标签

### 3.3 中央剧情/对话区（Story Log）
区分消息类型，各自视觉不同：
- `entry-narrator`：斜体旁白，左侧蓝色竖线
- `entry-dialogue`：NPC 气泡 / 玩家气泡（右对齐）
- `entry-system`：紫色小字，左侧竖线
- `entry-investigate`：调查结果显示
- `entry-clock`：时钟分隔线
- `entry-gameover`：结局金色卡片

### 3.4 右侧状态栏（Right Sidebar）
- 当前状态（时段/阶段/位置）
- 持有证据（标签卡片）
- 公共事件记录

### 3.5 底部动作按钮区（Action Bar）
- 移动 / 调查 / 推进 / 指认分类显示
- enabled=false 的按钮禁用 + 显示 hint

### 3.6 对话输入弹层（Talk Modal）
- NPC 头像 + 名字 + 身份
- 预设问题快捷按钮
- 文本输入框
- 发送/取消按钮

## 4. 场景布局策略

每个地点用 CSS class 和文字描述区分氛围：
- 大厅、书房、厨房、走廊、餐厅等各有文字描述
- 当前地点名显示在场景舞台顶部
- 场景切换使用 `scene-flash` 覆盖层

---

## 5. 人物形象布局策略

- 每个 NPC 有稳定颜色 + 首字母头像
- 颜色与 NPC 角色对应（陈伯=金，林婉=红，苏苏=粉等）
- 头像在对话气泡和 NPC 卡片中统一使用
- 不使用真实图片，使用 CSS + 文字模拟

---

## 6. 与 `/api/action` 的关系

所有交互走 `/api/action`：
- 移动、调查、推进、指认：直接调用
- 盘问 NPC：点击"盘问"按钮 → 弹出输入层 → 输入后调用 `/api/action`，`type='talk'`

页面初始化：`POST /api/session`
状态刷新：每次 `/api/action` 响应中携带最新 `state`（含 `available_actions`）

---

## 7. 当前限制

- 部分场景/人物/证据仍使用 CSS 模拟，真实美术资源待接入
- 场景切换使用纯 CSS 动画 + 背景图片（manifest 管理）
- NPC 头像优先使用 manifest 中的真实立绘，缺失时 fallback 到字母头像
- 存档仍为单文件（`saves/save.json`）

## 7.1 视觉资产接入状态

UI 已从纯 CSS 模拟升级为**资产驱动**：

- 场景背景：`scene-stage` 底部叠加 `scene-bg-img`（manifest 管理）
- 人物立绘：NPC 卡片 + 对话气泡中的 avatar 优先加载 portrait
- 证据图标：证据卡片中的图标优先加载 evidence icon
- 缺图处理：三层 fallback（真实图 → placeholder → CSS 回退）

资源接入无需改代码，只需要在 `static/assets/` 放入图片并确保 manifest 路径正确。

### 7.2 主入口显示策略

- `/` 中的场景图作为氛围背景使用，采用 `object-fit: cover` + 暗色遮罩，优先保证文字可读性。
- 首批人物素材为全身透明底立绘，不再压进 32px 圆形裁切，而是以纵向缩略头像显示在 NPC 卡片和对话弹层中。
- 证据图标使用独立的小面板承载，优先保证轮廓辨识和材质细节，而不是只当作 16px 装饰符号。

## 8. 当前 P2 深化内容

### 8.1 后端结构化字段增强

`_world_to_dict` 新增字段：

| 字段 | 内容 |
|------|------|
| `npcs` | 每个 NPC 含 name / public_role / location / alive / talked / present / suspicion_of_player |
| `current_location` | name / description / theme / mood / color / present_npcs |
| `evidence_details` | 每条证据含 name / source / points_to / level / icon |
| `progress` | evidence_count / talked_count / npc_count / clock / max_clock / phase / event_count |

`game/rules.py` 新增：
- `EVIDENCE_METADATA`：证据元数据（source / points_to / level / icon）
- `LOCATION_THEMES`：地点主题（theme / mood / color）

### 8.2 场景视觉系统

每个地点有独立 CSS `data-theme` 背景：
- `hall` / `study` / `kitchen` / `dining` / `security` / `corridor` / `room`
- 渐变 + 伪元素左边框颜色区分场景氛围
- 地点主题色映射到场景舞台顶部竖线

### 8.3 人物视觉系统

每个 NPC 有前端配置 `NPC`（color / letter / role / archetype）：
- 字母头像 + 颜色一眼区分角色
- NPC 卡片含：在场/已对话/警觉度进度条/死亡状态
- 警觉度颜色：红（>60）/ 金（>30）/ 蓝（≤30）

### 8.4 证据板升级

从"标签列表"升级为"证据卡片"：
- 图标 + 证据名 + 来源/指向 + 重要性标签（关键/重要/线索）
- 空状态显示引导文案

### 8.5 时间线栏

Header 下方新增 `timeline-bar`：
- 时段节点进度条（已过=金色/当前=红脉冲/未到=灰）
- 阶段徽章（晚宴/调查/对峙）当前阶段高亮
- 右下角事件统计（事件数/证据数/对话数）

### 8.6 剧情区优化

- 按钮 loading 状态防连点
- 对话提交后自动关闭弹层
- 不同消息类型独立 CSS 样式

### 8.7 P3 主舞台角色立绘层

新增主舞台人物层，是为了把首批真实人物素材从“缩略头像”提升为当前地点的主视觉元素，让 `/` 更接近视觉小说 / 推理游戏的场景演出体验。

它与侧栏 NPC 卡片分工明确：
- 主舞台人物层负责沉浸展示、地点在场感和点击盘问入口
- 侧栏 NPC 卡片继续负责位置、是否已对话、警觉度和状态信息

角色站位规则保持简单稳定：
- 1 人在场：居中显示
- 2 人在场：左右分布
- 3 人在场：左 / 中 / 右分布，中央角色略大
- 4 人以上：主舞台仅显示前 3 人，其余仍在侧栏卡片中显示

资源加载规则：
- 优先使用 `manifest.characters[npc.name].portrait`
- portrait 加载失败时回退到 placeholder
- placeholder 也失败时，再回退到文字 / CSS 头像

当前限制：
- 站位规则仍是固定模板，不做复杂遮挡与构图计算
- 目前主舞台层只展示“当前地点在场角色”的前 3 人，更多人物仍依赖侧栏查看
- 缺少真实立绘的角色仍以 placeholder 为主，视觉一致性取决于后续素材补齐

## 9. 下一轮 UI 迭代建议

1. **接入真实美术图**：按 `docs/IMAGE_PROMPTS.md` 生成首批 5 个样张，验证风格方向
2. **场景背景**：地点切换时 CSS 背景色温动态变化（书房偏暖、保安室偏冷）
3. **证据板**：卡片网格 + 证据来源地点标记
4. **人物关系**：NPC 之间关系可视化（谁怀疑谁）
5. **时间轴**：在侧边或底部显示更详细的时钟推进时间线
6. **map.html**：评估是否能作为地图 UI 原型保留
7. **移动端适配**：当前为桌面端，暂无移动端布局

## 10. /map 页面定位

`/map` 是早期 Canvas 实验页。

它用于验证地图点击、NPC 点击、房间跳转等交互。

它不是主游戏入口，也不是最终 UI 方向。

后续如果保留，应重构为“场景探索模式”，而不是继续基于圆圈 + 网格深化。

## 10.1 第二批素材显示策略

第二批场景素材（厨房、餐厅、走廊、保安室）整体比首批大厅 / 书房更暗，主界面继续保留暗色遮罩和文字保护层，但会适度提高背景图可见度，避免真实场景只剩下模糊氛围。

第二批人物素材（苏苏、王总、阿福、小张）延续主舞台立绘层展示，不再退回缩略头像思路。考虑到这批人物大多是半身偏中景构图，单人和双人站位会略微放宽宽度和高度，让人物在舞台上更像“当前地点角色”，同时继续保证不遮挡底部行动按钮和剧情区。

缺图策略不变：
- 优先真实 portrait
- 失败时回退 placeholder
- placeholder 再失败时回退文字 / CSS 头像
