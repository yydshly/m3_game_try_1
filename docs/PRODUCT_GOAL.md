# PRODUCT_GOAL.md — 项目目标定义

> 本文档定义《孤岛晚宴》是什么、不是什么，以及 MiniMax-M3 在游戏中的职责边界。

---

## 1. 项目一句话定义

《孤岛晚宴》是一个以用户 UI 操作为主入口，由 MiniMax-M3 参与角色演绎、剧情推动、关键决策和结局裁判的 AI 互动推理游戏原型。

---

## 2. 项目不是做什么

- **不是普通聊天机器人**——用户通过结构化动作（对话/调查/移动/指认）推进游戏，不是自由聊天
- **不是纯文本续写器**——有明确规则层约束动作合法性，M3 不能随意修改状态
- **不是传统固定脚本 AVG**——NPC 有自主记忆和博弈能力，剧情会因玩家行为涌现变化
- **不是大而全游戏引擎**——专注单一剧本的体验打磨，不做通用引擎
- **不是复杂多用户 SaaS**——单人体验，暂不支持联机、账号、好友等社交功能

---

## 3. 项目当前核心目标

围绕以下原则：

```
用户通过 UI 操作推进游戏
系统把 UI 操作转成 PlayerAction
规则层决定动作是否合法
MiniMax-M3 只在需要语言生成、角色判断、叙事裁判时参与
WorldState 是唯一真相源
UI 始终展示当前状态、可行动作、证据、人物、地点、事件
```

**当前只支持《孤岛晚宴》固定剧本。**
**当前重点是跑通 UI 驱动闭环，不急着生成无限剧本。**

---

## 4. MiniMax-M3 的定位

### A. 运行时参与（M3 实际参与游戏运行）

| Agent | 职责 | 调用时机 |
|-------|------|---------|
| `NPCDialogueAgent` | 生成 NPC 对话回复 | 玩家发起 talk 动作 |
| `NarratorAgent` | 生成场景氛围旁白 | 时段推进（advance） |
| `NPCDecisionAgent` | NPC 关键时刻决策 | 林婉证据暴露时 |
| `DirectorAgent` | 结局裁判（verdict + summary）| 玩家发起指认，或 clock 到顶 |

### B. 设计时参与（后续阶段，非运行时）

| Agent | 职责 | 限制 |
|-------|------|------|
| `ScenarioDesignerAgent` | 生成新剧本蓝图 | 不能直接写入运行时 WorldState |
| `NPCDesignerAgent` | 生成 NPC 设定 | 需人工或规则校验后转成 scenario_data |
| `EvidenceDesignerAgent` | 生成证据链 | 同上 |
| `LevelDesignerAgent` | 生成地点/事件/阶段条件 | 同上 |

**关键约束：设计时 Agent 不能直接写入运行时 WorldState。必须先生成 GameBlueprint / ScenarioDraft，再经人工或规则校验后转成 scenario_data.py。**

---

## 5. 当前 MVP 边界

```
当前只支持《孤岛晚宴》固定剧本。
当前重点是跑通 UI 驱动闭环，不急着生成无限剧本。
当前不做账号、不做数据库、不做支付、不做多人在线。
当前 UI 优先稳定 /api/action，不做复杂前端框架。
```

---

## 6. 当前不做什么（再次强调）

- 不引入数据库、多用户系统
- 不做大模型替换（保持 MiniMax-M3）
- 不做复杂 AI Agent 编排框架
- 不做地图/立绘/音效（除非单独出了 PLAN_氛围层）
- 不做 Phase 5+ 的复杂 SSE 多人联机
